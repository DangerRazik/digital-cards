# Digital Cards — электронные визитки

Angular 21 + TypeScript + обычный CSS. Отдельное приложение для просмотра визиток.
Сейчас это локальный прототип с одним примером, без backend, базы данных и авторизации.
Административные экраны здесь не создаются.

## Запуск

На текущем компьютере обычный `npm` использует Node 18. Для этого проекта используйте:

```powershell
.\npm-local.ps1 ci
.\start-local.ps1
```

Перед повторной установкой остановите работающий предпросмотр через Ctrl+C в его терминале:
иначе Windows может заблокировать файл `esbuild.exe`. Не запускайте `npm ci` одновременно с `ng serve`.
`npm-local.ps1` выбирает Node 24 для npm и дочерних команд только на время выполнения, не меняя системные настройки.
Проверки: `.\npm-local.ps1 test`; сборка: `.\npm-local.ps1 run build`.

### Обычный запуск после самостоятельного переключения Node

Нужен Node.js 24 LTS (в проекте есть `.nvmrc`). Установленный на компьютере Node 18 для этой версии Angular не подходит.

Откройте терминал в папке `C:\Users\Пользователь\Desktop\digital-cards`:

```powershell
npm ci
npm start
```

Откройте http://localhost:4200/stecevich-valeriy . Корневой адрес перенаправляет на этот пример.
Неизвестный slug показывает «Визитка не найдена».

На текущем компьютере можно запустить без смены системной версии Node:

```powershell
.\start-local.ps1
```

Этот скрипт использует уже установленный Node 24 из среды Codex только для текущего запуска.
Он не меняет системный PATH и настройки других проектов.

Проверки и сборка при активном Node 24:

```powershell
npm test
npm run build
```

Готовая сборка: `dist/public-card/browser`. Для будущего размещения потребуется отдавать `index.html`
на маршрут `/{slug}`. Серверная выдача настоящего HTTP 404 и SEO будут решаться вместе с backend.

## Как читать код

| Файл | Назначение |
| --- | --- |
| `src/main.ts` | Запуск Angular и маршруты публичной страницы |
| `src/app/card.model.ts` | Типы данных, проверка видимости и допустимых web-ссылок |
| `src/app/demo-card.ts` | Единственный пример визитки; редактировать данные для локальных проверок здесь |
| `src/app/card-page.component.ts` | Подготовка данных страницы, ссылки, действие сохранения |
| `src/app/card-page.component.html` | Разметка и условия отображения блоков |
| `src/app/card-page.component.css` | Компоновка страницы, размеры, адаптивность, состояния кнопок |
| `src/styles.css` | Общие стили, локальные шрифты, семантические переменные цветов |
| `src/app/vcard.ts` | Формирование и загрузка vCard 3.0, экранирование и перенос UTF-8 |
| `tests/vcard.test.ts` | Проверки формата контакта и исключения скрытых полей |
| `public/assets` | Локальные изображения и SVG-значки |

`CardField` — значение и переключатель `enabled`. Пустое или отключённое поле скрывается.
`blocks` — переключатели целых разделов. Например, `blocks.phones = false` скрывает оба телефона
и исключает их из `.vcf`. `blocks.address = false` также скрывает карту.
Для аватара приоритет: фото → логотип → инициалы. При ошибке загрузки изображения показываются инициалы.
Сайт и мессенджеры появляются только с допустимыми HTTP(S)-ссылками.

## Что проверить вручную

1. На ширинах 320, 390, 768 и 1440 px нет горизонтального скролла. На компьютере ширина визитки не превышает 560 px.
2. «Сохранить контакт» скачивает `stecevich-valeriy.vcf`. Откройте файл в адресной книге своего телефона и проверьте кириллицу, организацию и оба телефона.
3. Телефоны используют `tel:`, почта — `mailto:`. Не отправляйте сообщения на тестовые адреса.
4. В `demo-card.ts` отключите `workPhone.enabled` или очистите `email.value`: соответствующая карточка исчезнет.
5. Отключите `blocks.messengers`: весь ряд исчезнет. Отключите `blocks.map`: адрес останется, карта исчезнет.
6. Отключите `photo.enabled` и `logo.enabled`: появятся инициалы. Введите длинное ФИО: оно должно переноситься.
7. Увеличьте масштаб браузера до 200%, пройдите по ссылкам клавишей Tab: фокус виден, действия доступны.
8. Откройте `/unknown-card`: отображается отсутствие визитки.

Телефоны и email демонстрационные. Мессенджеры открывают сайты сервисов, а не чаты сотрудника:
его персональных ссылок у нас пока нет. В eXpress использован условный SVG-значок чата, не официальный логотип.
Карта — внешний виджет Яндекса с поиском адреса, ей нужен интернет; ссылка на большую карту доступна отдельно.
Проверка импорта контакта в реальные iOS/Android остаётся за пользователем.

## Границы этапа и следующий шаг

В frontend отсутствуют API записи и интерфейс редактирования, но это ещё не серверная защита:
backend на этом этапе отсутствует. После проверки UI создадим отдельный backend и административное приложение.
Публичный API должен выдавать **только снимок опубликованной версии и разрешённые поля**.
Нельзя передавать черновики или приватные значения в браузер и полагаться на `enabled` для защиты.
`enabled` сейчас нужен для локальной проверки отображения и экспорта.

Постоянный `slug` будет сохраняться при смене ФИО. QR будет кодировать только URL.
Редактирование опубликованной визитки будет создавать черновик; публикация заменит публичный снимок.
Эти операции, авторизация, загрузки и QR пока не реализованы.
Светлая тема готова; переменные `--page`, `--surface`, `--text`, `--accent` и другие позволяют позже добавить dark theme.
Настоящее переключение тем сейчас не добавлено.
