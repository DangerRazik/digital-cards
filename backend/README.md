# Backend — этап 5

NestJS 11, TypeScript, драйвер `pg`, PostgreSQL 17. API доступен только на `127.0.0.1:3000`.

## Файлы

- `src/main.ts` — запуск сервера и общий префикс `/api`.
- `src/app.module.ts` — связывает контроллер и сервисы NestJS.
- `src/cards.controller.ts` — публичный маршрут `GET /api/public/cards/:slug`.
- `src/cards.service.ts` — проверяет slug и запрашивает опубликованный снимок параметризованным SQL.
- `src/database.service.ts` — пул подключений; учётная запись имеет только право чтения представления.
- `src/public-card.ts` — белый список полей ответа; удаляет отключённые значения, внутренние поля и недопустимые URL.
- `database/001-cards.sql` — таблица визиток, представление для публичного чтения и права доступа.
- `database/demo-card.json` — исходные данные примера для первой подготовки базы, не источник данных страницы.
- `scripts/setup-database.cjs` — применяет схему и добавляет примеры, не перезаписывая существующие визитки.
- `tests/api.test.cjs` — интеграционные проверки HTTP API и прав настоящей PostgreSQL.

## Данные

Одна строка `cards` содержит постоянный `slug`, статус, `draft`, `published_snapshot` и даты.
Содержимое визитки хранится в JSONB: её поля и переключатели образуют один документ.
Это позволяет хранить целую опубликованную версию отдельно от редактируемого черновика без десятков вспомогательных таблиц.
Статус, slug и даты остаются обычными колонками с ограничениями PostgreSQL.
Структура черновика проверяется в create-card.input.ts и card-draft.input.ts. Публичный ответ отдельно фильтруется в public-card.ts.

`published_cards` — представление, содержащее только опубликованные снимки.
Роль `cards_public` может читать только его. Она не имеет доступа к таблице `cards`, черновикам и записи.
Сервис очищает опубликованный снимок перед отправкой, даже если в нём сохранились выключенные значения.
Это серверное ограничение: скрытие полей в Angular не считается защитой.

Пример `stecevich-valeriy` опубликован; его черновик специально содержит другое имя.
`draft-example` существует в БД, но публичный API возвращает 404.
При остановке БД запрос возвращает 503 без строки подключения или паролей.
Для публичных визиток POST, PUT, PATCH и DELETE отсутствуют и возвращают 404.
Маршруты регистрации и входа отделены префиксом `/api/admin/auth`.

## Проверка

Из корня `digital-cards`:

```powershell
.\start-db.ps1
.\npm-local.ps1 -Project backend run build
.\npm-local.ps1 -Project backend test
```

Тесты запускают собственный HTTP сервер на свободном порту и создают временные строки с уникальными slug.
В `finally` удаляются только эти строки. Основной пример не изменяется.
Файл `.env` содержит реквизиты трёх ограниченных ролей: публичного чтения, авторизации и создания черновиков. Реквизиты владельца доступны локальному setup/test инструменту в `.local/db-config.json`.

Отдельное приложение `admin-web` поддерживает регистрацию, вход и выход.
В кабинете доступны список собственных визиток и создание черновиков.
Редактирование черновиков реализовано. Загрузка файлов, предпросмотр и публикация будут следующими этапами.
Нельзя просто добавить запись в этот контроллер или выдать роли публичного API права владельца.


## Путь запроса авторизации

`admin-web/AuthService` → `AuthController` → `AuthService` → PostgreSQL (`users`, `sessions`).

| Метод и маршрут | Назначение |
| --- | --- |
| POST /api/admin/auth/register | Создать пользователя и сессию, вернуть id/email |
| POST /api/admin/auth/login | Проверить пароль и установить новую сессию |
| GET /api/admin/auth/me | Проверить сессию через SessionGuard и вернуть id/email |
| POST /api/admin/auth/logout | Удалить сессию из БД и очистить cookie |

`AuthRequestGuard` проверяет Origin для POST и ограничивает частоту запросов входа/регистрации.
Для будущих защищённых операций нужны и проверка сессии, и проверка владельца конкретной визитки.
Один SessionGuard не даёт права работать с чужими записями.

Пароль хешируется с помощью scrypt. Cookie содержит случайный токен; в БД хранится только его SHA-256 хеш.
Роль `cards_auth` не имеет прав на `cards`. Роль `cards_public` не читает пользователей и сессии.
Тесты `tests/auth.test.cjs` проверяют реальные HTTP-запросы, истечение сессии и права PostgreSQL.

Миграция `002-auth.sql` добавляет таблицы и права; существующие визитки не меняются.
Скрипт `db:setup` создаёт локальную роль авторизации и дополняет `.env`, сохраняя текущие настройки.
Условия развёртывания без Docker и параметры окружения описаны в корневом README.md.


## Собственные визитки

`GET /api/admin/cards` возвращает краткий список визиток пользователя из сессии.
`POST /api/admin/cards` создаёт только черновик. Обязательны firstName и lastName;
дополнительно принимаются middleName, jobTitle и organization.
Slug всегда генерируется сервером один раз и сохраняется в базе. ФИО вычисляется из частей имени.
При некорректном вводе возвращается 400, без сессии — 401.
Чужой owner_user_id в query не меняет фильтр; неизвестные поля в теле POST отклоняются.

`SessionGuard` проверяет вход; `AuthRequestGuard` проверяет Origin/JSON и частоту запросов.
`AdminCardsService` использует EDITOR_DATABASE_URL с отдельной ролью cards_editor.
Публичный URL строится из PUBLIC_CARD_ORIGIN; для черновика ссылка пока не работает.
В ответ списка не включается весь draft, owner_user_id, published_snapshot или данные аккаунта.

`003-card-owners.sql` добавляет nullable owner_user_id: это сохраняет существующие примеры
без автоматического присвоения их новому пользователю. Для новых записей владелец обязателен в логике сервиса.
Тесты admin-cards.test.cjs создают два временных аккаунта, проверяют их изоляцию
и удаляют только собственные тестовые записи в finally.


## Редактор

- `GET /api/admin/cards/:id/draft` — краткие сведения и редактируемые поля собственной визитки.
- `PUT /api/admin/cards/:id/draft` — полная замена редактируемых данных черновика и обновление даты изменения.

Оба SQL-запроса фильтруют по id визитки и owner_user_id из сессии.
Чужая и отсутствующая запись возвращают одинаковый 404. Сохранение не изменяет slug,
owner_user_id, status, published_snapshot и published_at. Роль cards_editor может обновлять
только draft и updated_at благодаря миграции 004-edit-drafts.sql.

Тело PUT содержит firstName, lastName, middleName, поля вида { value, enabled }, messengers и blocks.
Отдельные displayName, slug, статус или владелец в теле запроса запрещены.
Неизвестные поля внутри messengers, blocks и полей контактов тоже отклоняются.
Выключенные значения сохраняются в личном черновике; публичный преобразователь их удаляет.
Для ссылок разрешены HTTP/HTTPS без учётных данных, для изображений также локальные /assets/… пути.
Исходные пароли, cookie и другие данные аккаунта не входят в ответ редактора.

Сборка выполняется пользователем. Тесты читают dist, поэтому их необходимо запускать после актуальной сборки backend.
